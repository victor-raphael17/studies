Vue do zero
Vue 3 · Vite · um componente por arquivo

A página segue
o valor.

Você guarda os dados. O Vue mantém a página em sincronia com eles. A ideia é essa — todo o resto aqui embaixo é só como dizer isso.

você guarda um valor const count = ref({{ count }})
você escreve no template, uma vez <button>{{ count }}</button>
← clique aqui

O Vue não carregou do CDN. Conecte-se à rede e recarregue a página — os exemplos ao vivo precisam dele.

Um clique mudou uma variável. O número no código e o rótulo do botão — os dois seguiram junto. Você não escreveu uma linha sequer de manipulação de DOM.

01

Criar o projeto

Um comando monta a estrutura, instala o Vue e liga um servidor que recarrega a página sozinho toda vez que você salva um arquivo.

terminal 
npm create vue@latest

cd meu-projeto
npm install
npm run dev
cuidado Ele faz uma sequência de perguntas. Para este tutorial, responda Não para todas — inclusive TypeScript, que já vem marcado como Sim. Se você só apertar Enter, acaba com um projeto em TypeScript e os arquivos terão outra extensão.
o que importa da estrutura 
meu-projeto/
├─ index.html
├─ vite.config.js
├─ package.json
└─ src/
   ├─ main.js        <- liga o Vue na página
   ├─ App.vue        <- o componente raiz
   ├─ assets/        <- css e imagens
   └─ components/    <- os seus componentes
nota O npm run dev mostra um endereço, normalmente http://localhost:5173. Deixe ele aberto no navegador enquanto edita: cada vez que você salvar, a tela muda sozinha.
nota O projeto vem com uma tela de boas-vindas de exemplo. Pode apagar tudo dentro de src/components/ e esvaziar o App.vue — nada aqui depende disso.
02

Um componente é um arquivo .vue

Três blocos no mesmo arquivo: o estado que a tela usa, o que ela mostra e o estilo que vale só ali dentro. É essa a unidade de trabalho do Vue — você vai escrever dezenas deles.

src/App.vue 
<script setup>
import { ref } from 'vue'

const message = ref('Hello from Vue')
</script>

<template>
  <p>{{ message }}</p>
</template>

<style scoped>
p { color: #42b883; }
</style>
src/main.js — já vem pronto 
import { createApp } from 'vue'
import App from './App.vue'

createApp(App).mount('#app')
rodando

{{ message }}

o que o setup faz Tudo que você declara no topo do <script setup> já fica visível para o <template>. Sem return, sem registrar nada, sem repetir nome.
o que o scoped faz Prende o CSS a este componente. Sem ele, aquele p { } pintaria de verde todo parágrafo do aplicativo.
03

Estado mora em ref()

Um ref é uma caixa em volta de um valor. O Vue observa a caixa. Troque o que está dentro e tudo que lê aquele valor se redesenha — esse é o único mecanismo que você precisa entender.

javascript 
import { ref } from 'vue'

const count = ref(0)

count.value          // read it  -> 0
count.value = 5      // change it
count.value++        // same thing

const user = ref({ name: 'Ada' })
user.value.name = 'Grace'   // objects work too
a regra que pega todo mundo

No JavaScript — sempre .value

No template — nunca .value

✓ count.value++ dentro de uma função

✓ {{ count }} dentro do template

✗ {{ count.value }} — não mostra nada

por quê O Vue desembrulha o ref sozinho na hora de renderizar, porque digitar .value em toda chave dupla seria sofrido. Essa assimetria é o preço.
04

Responder a cliques com @click

@ é o atalho de v-on: "execute isto quando tal evento acontecer". Mude o estado dentro da função e pare por aí — você nunca seleciona um elemento nem escreve em textContent.

src/components/Counter.vue 
<script setup>
import { ref } from 'vue'

const count = ref(0)

function reset() {
  count.value = 0     // .value here
}
</script>

<template>
  <p>count: {{ count }}</p>
  <button @click="count++">add one</button>
  <button @click="reset">reset</button>
</template>
rodando

count: {{ count }}

nota Dentro do template é count++, não count.value++. A regra do passo anterior vale só no JavaScript.
nome completo @click é a forma curta de v-on:click. As duas funcionam; na prática ninguém escreve a longa, mas você vai encontrá-la na documentação.
05

Campos de formulário com v-model

Digitar atualiza o ref; mudar o ref atualiza o campo. Uma linha no lugar de um listener e um setter.

src/components/NameField.vue 
<script setup>
import { ref } from 'vue'

const name = ref('')
</script>

<template>
  <input v-model="name" placeholder="your name">
  <p>Hello, {{ name }}</p>
  <button @click="name = ''">clear</button>
</template>
rodando

Hello, {{ name || '…' }}

nota Funciona em <input>, <textarea> e <select>. Em caixas de seleção ele guarda um booleano em vez de texto.
06

Valores derivados com computed()

Quando um valor é calculado a partir de outros, não guarde — calcule. Ele se atualiza quando os ingredientes mudam e fica em cache quando não mudam.

src/components/FullName.vue 
<script setup>
import { ref, computed } from 'vue'

const first = ref('Ada')
const last  = ref('Lovelace')

const full = computed(() => {
  return first.value + ' ' + last.value
})

const initials = computed(() =>
  first.value[0] + last.value[0]
)
</script>

<template>
  <p>{{ full }} ({{ initials }})</p>
</template>
rodando

{{ full }} ({{ initials }})

cuidado É {{ full }}, não {{ full() }}. Um computed se lê como valor, não como função — no JavaScript ele continua sendo full.value.
07

Listas e condições

v-for repete um elemento para cada item. v-if tira o elemento do HTML quando a condição é falsa. v-show deixa ele lá e só esconde. Os três reagem aos dados embaixo deles.

src/components/TaskList.vue 
<script setup>
import { ref } from 'vue'

const tasks = ref([
  { id: 1, text: 'learn ref' },
  { id: 2, text: 'learn components' }
])

function add() {
  tasks.value.push({ id: Date.now(), text: 'new task' })
}
</script>

<template>
  <ul>
    <li v-for="task in tasks" :key="task.id">
      {{ task.text }}
    </li>
  </ul>

  <p v-if="tasks.length === 0">Nothing yet.</p>
  <p v-else>{{ tasks.length }} to go.</p>

  <p v-show="tasks.length > 3">That is a long list.</p>
</template>
rodando
  • {{ task.text }}

Nothing yet.

{{ tasks.length }} to go.

That is a long list.

cuidado Todo v-for precisa de um :key único e estável — é assim que o Vue liga cada item ao seu elemento entre um render e outro. O índice do array funciona até você reordenar ou apagar algo do meio.
v-if ou v-show? v-if não cria o elemento; v-show cria e aplica display: none. Use v-show no que alterna o tempo todo e v-if no resto.
08

Atributos vivos com :

Um atributo comum é um texto fixo. Coloque dois-pontos na frente e o valor vira uma expressão JavaScript que continua acompanhando o estado.

template 
<template>
  <!-- fixed -->
  <button title="save">save</button>

  <!-- live -->
  <button :disabled="text === ''">save</button>
  <img :src="user.avatar" :alt="user.name">

  <!-- classes: key = class, value = when -->
  <span :class="{ done: task.finished }">{{ task.text }}</span>
</template>
rodando

{{ text || 'nada para salvar' }}
os dois prefixos : é o atalho de v-bind — dado entrando no elemento. @ é o atalho de v-on — evento saindo dele. A sintaxe é essa, e acabou.
09

Props descem, eventos sobem

O pai entrega dados ao filho por props. O filho pede mudanças emitindo um evento. Os dados correm em uma direção só, e é por isso que ainda dá para entender o código às três da manhã.

src/components/TaskRow.vue — o filho 
<script setup>
defineProps(['text', 'done'])
const emit = defineEmits(['toggle'])
</script>

<template>
  <li>
    <input type="checkbox" :checked="done"
           @change="emit('toggle')">
    <span :class="{ done }">{{ text }}</span>
  </li>
</template>
src/App.vue — o pai 
<script setup>
import { ref } from 'vue'
import TaskRow from './components/TaskRow.vue'

const tasks = ref([
  { id: 1, text: 'read this page', done: true }
])
</script>

<template>
  <ul>
    <TaskRow
      v-for="task in tasks"
      :key="task.id"
      :text="task.text"
      :done="task.done"
      @toggle="task.done = !task.done" />
  </ul>
</template>
rodando

{{ tasks.filter(t => t.done).length }} / {{ tasks.length }} done

cuidado Props são somente leitura. O filho não consegue escrever em done — ele emite toggle e quem decide é o pai. Tentar atribuir a uma prop gera um aviso no console e não faz nada.
de onde saem essas duas funções defineProps e defineEmits não precisam de import. São macros do compilador e só existem dentro de <script setup>.
o nome da tag Dentro de um .vue a tag é <TaskRow>, igual ao nome do import — o compilador cuida disso. Importar o componente é o que o registra; não existe lista de components para manter.
os dois arquivos, inteiros

É isso o básico.

Abaixo está um aplicativo funcionando que usa todas as ideias desta página, e nada além delas. Cole nos dois arquivos do seu projeto e comece a apagar coisas — é o jeito mais rápido de descobrir o que cada linha estava segurando.

src/components/TaskRow.vue 
<script setup>
defineProps(['text', 'done'])
const emit = defineEmits(['toggle', 'remove'])
</script>

<template>
  <li>
    <input type="checkbox" :checked="done" @change="emit('toggle')">
    <span :class="{ done }">{{ text }}</span>
    <button @click="emit('remove')">x</button>
  </li>
</template>

<style scoped>
.done { text-decoration: line-through; opacity: .55; }
</style>
src/App.vue 
<script setup>
import { ref, computed } from 'vue'
import TaskRow from './components/TaskRow.vue'

const title = ref('Today')
const draft = ref('')
const tasks = ref([
  { id: 1, text: 'read this page', done: true },
  { id: 2, text: 'build something',  done: false }
])

const left = computed(() =>
  tasks.value.filter(t => !t.done).length
)

function add() {
  if (draft.value === '') return
  tasks.value.push({ id: Date.now(), text: draft.value, done: false })
  draft.value = ''
}

function remove(id) {
  tasks.value = tasks.value.filter(t => t.id !== id)
}
</script>

<template>
  <h3>{{ title }}</h3>

  <input v-model="draft" @keyup.enter="add" placeholder="new task">
  <button @click="add" :disabled="draft === ''">add</button>

  <ul>
    <TaskRow
      v-for="task in tasks"
      :key="task.id"
      :text="task.text"
      :done="task.done"
      @toggle="task.done = !task.done"
      @remove="remove(task.id)" />
  </ul>

  <p v-if="tasks.length === 0">Nothing to do.</p>
  <p v-else>{{ left }} left of {{ tasks.length }}</p>
</template>
rodando

{{ title }}

Nothing to do.

{{ left }} left of {{ tasks.length }}

Três coisas que valem a pena saber em seguida

  • Onde ficam os estilos globais. O <style scoped> vale só dentro do componente. O que é do aplicativo inteiro vai em src/assets/main.css, que o main.js já importa.
  • Quando o aplicativo crescer, você vai querer Vue Router para ter várias telas e Pinia para estado compartilhado entre componentes distantes. Os dois são perguntas do npm create vue@latest — dá para adicionar depois.
  • A documentação oficial está em pt.vuejs.org, traduzida. Escolha a aba Composition API, que é o estilo desta página.
