    Camadas TCP/IP

    o que cada camada resolve

    Rede é dividida em camadas para que cada parte resolva um problema só. A de baixo entrega o quadro para o vizinho no mesmo cabo. A de cima entrega o dado para o programa certo. Clique numa camada para ver o que ela faz.

    Encapsulamento: o que o seu texto vira na rede

    Cada camada embrulha o que veio de cima e coloca o próprio cabeçalho na frente. No destino acontece o contrário: cada camada tira o cabeçalho dela e entrega o miolo para a de cima.

    O nome dos dados muda conforme a camada: dado na aplicação, segmento no transporte, pacote na rede, quadro no enlace. É a mesma informação com embrulhos diferentes.

    Endereçamento IPv4 e IPv6

    o número que identifica a interface

    O endereço IPv4 tem 32 bits escritos como quatro números de 0 a 255, um por octeto. Escrever em decimal é só conveniência: quem decide tudo é o binário. Mude os octetos e veja os bits.

    IPv6: encurtar e expandir

    IPv6 tem 128 bits em oito grupos de quatro dígitos hexadecimais. Duas regras encurtam a escrita: zeros à esquerda de cada grupo somem, e a maior sequência de grupos zerados vira ::, uma vez só no endereço.

    Máscara de rede e CIDR

    onde termina a rede e começa o host

    A máscara diz quantos bits da esquerda identificam a rede. O resto identifica o host dentro dela. A notação CIDR é só o número desses bits: /24 quer dizer 24 bits de rede e 8 de host.

    O endereço de rede é o que tem todos os bits de host em zero, e o broadcast é o que tem todos em um. Por isso sobram dois endereços a menos para as máquinas.

    Regra de bolso que resolve quase tudo: cada bit a mais no prefixo divide a quantidade de endereços pela metade. /24 tem 256, /25 tem 128, /26 tem 64.

    Sub-redes

    dividir um bloco em blocos menores

    Dividir uma rede é pegar bits emprestados da parte de host e transformar em parte de rede. Um /24 vira dois /25, quatro /26, oito /27, e assim por diante.

    ARP

    do endereço IP para o endereço MAC

    Dentro de uma mesma rede local, o quadro é entregue pelo endereço MAC, não pelo IP. O ARP é quem descobre o MAC correspondente a um IP. Avance passo a passo e veja o que acontece no cabo.

    O detalhe que confunde quase todo mundo: quando o destino está fora da rede local, o ARP não pergunta pelo IP do destino. Ele pergunta pelo MAC do gateway. O IP de destino continua sendo o original dentro do pacote.

    Tabela de roteamento, next hop e rota default

    como o roteador escolhe por onde mandar

    O roteador olha o IP de destino e procura na tabela qual rota casa. Quando mais de uma casa, vence a de prefixo mais longo, ou seja, a mais específica. Se nenhuma casar, vale a rota default 0.0.0.0/0, que casa com tudo por ser a menos específica de todas.

    Next hop é o endereço do próximo roteador, não do destino final. Um pacote atravessa a internet sendo repassado de vizinho em vizinho, e cada um só sabe o passo seguinte.

    Roteamento estático, dinâmico e OSPF

    métrica, vizinhança e convergência

    Rota estática é escrita à mão e não muda sozinha. Roteamento dinâmico faz os roteadores trocarem informação e recalcularem o caminho quando a rede muda. O OSPF é o exemplo clássico dentro de uma organização.

    Antes de trocar rotas, dois roteadores viram vizinhos: mandam pacotes hello no enlace, se reconhecem e formam adjacência. Depois cada um monta o mapa completo da rede e roda Dijkstra para achar o caminho de menor custo. Custo é a métrica, e por padrão vem da banda do enlace, não da quantidade de saltos.

    Calcular o caminho de R1 até R6

    Clique num enlace para derrubá-lo e veja o OSPF convergir para outro caminho. O número em cada enlace é o custo.

    Repare que o melhor caminho nem sempre é o de menos saltos. Somar custos baixos por um trajeto mais longo pode sair melhor que dois enlaces caros. É exatamente isso que separa métrica de contagem de saltos.
